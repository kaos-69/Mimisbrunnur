The software/firmware for the reader is created in the Arduino environment. The main file is Mimisbrunnur.ino. At the start, there is alengthy comment detailing the various software libraries used. The files strings.h and styles.h are used to offload some declarations and functions from the main file. Icons are stored in icons.h, and FreeSans*.h hold the font in it's four variants.

When reading, the program only processes one page at a time. Styles, that is the formatting applied to the text (margins, font variants, underline etc.) are either preprocessed  and held in memory (for external and internal stylesheets), or ingested along with the page (for inline styles and tags). The program keeps track of the start and end of the page, along with the applicable style, so moving to the next page is simple. Moving to the previous page, however, means scanning through the document from the start to find the beginning of the page in question. This can take a few seconds, particularly near the end of large documents. The same technique is used for finding links within documents, and when skipping around to arbitrary locations.

# Memory structures

Styles (or style elements as they are referred to in some places in the code) are stored in 12 item (as set by `stecount` constant) arrays of 16-bit signed integers. This is more than sufficient to hold the attributes currently recognized by the software. Style attributes are indexed by constants named `SVR_*` (Style Value Reference), that are simple integer addresses. Item 0, or `SVR_FLAGS`, is a bitmapped set of boolean attributes. Of those, the lower order byte are values that need to be tracked character-by-character, like bold or underline, as opposed to values that apply to whole paragraphs, like alignment. Those boolean values are indexed by constants named `SFR_*` (Style Flag Reference), that are structures of type styleflagref. Those structures hold both bit mask and bit address for the values.

Now, a single array of this kind would be sufficient to hold the current style to be applied, but we also need to be able to regress to a previous state. For this, we have the global `stylestack` array, a 16 value (set by `stylestackmaxcount` constant) array of `stylemember` structures. Each `stylemember` holds a 16 character (as set by `tagsize` constant) array holding the name of a HTML tag, and a style definition array as described above. The size of the stack at each time is stored in global value `stylestackcount`. This never goes below 1, because the first value on the stack is the base style to be used when no other style has been defined. In use, whenever the current style is modified, whether by reference to a CSS tag or old style HTML tag, the style *before* modification is stored on the stack, along with the tag name that causes the modification. When a closing tag is encountered, it is compared against the tagname on top of the stack, and if matched, the old style is popped off the stack and restored.

For CSS to work, we need to hold a reference to all styles named in the stylesheets. This is done by the global `stylelist` array, a 256 element (set by `stylelistmaxcount` constant) array of of `stylelistmember` structures (not to be confused with the `stylemember` structures described above). These `stylelistmember` structures contain an Arduino String for the name of the style, a style array as described above, a 16-bit unsigned bitmask for flag attributes affected, and a 32-bit unsigned bitmask for the value attributes affected. The bitmasks are neccessary as each named style affects only a limited set of attributes.

# Support files

The program can create and use two types of support files. In the root of the SD card it will place "mimisbrunnur.pos". This file holds the path and filename of the document currently being read, the start of the current page, and any applicable styles. This allows the reader to return to the last known place on startup. This information can be stacked, so that if a link has been followed, it is possible to return to the place it was called from. If bookmarks are created they will be placed in a "*document*.bookmark" file, where *document* is the filename of the document itself.

Both file types share a similar structure based on variable length records. Each record is a reference to a specific page within a document. For bookmark files each record consists of:
- 8-bit flag value (currently only used to indicate whether the page starts with a fresh paragraph or a continuation from previous page).
- 32-bit starting point of the page within the document.
- 8-bit size of the style stack at that point
- The style stack

The mimisbrunnur.pos uses the same record structure, except that it prepends each record with a null-terminated character array containing the full path and filename of the document.
